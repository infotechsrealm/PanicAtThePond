### 2.4 Field encapsulation — partial by design

The rule is "No `public` fields". Converting `public X foo` → `[SerializeField] private X foo` is
**serialization-safe** because the field *name* is unchanged — every Inspector wiring survives.

| Category | Count | Action |
|---|---|---|
| Referenced only within their own type | **153** | ✅ Converted |
| Read cross-script (`GameManager.Instance.myFish`, …) | **161** | ⏸ Left public — needs a property + call-site updates |
| `static` / `const` / `readonly` / already-attributed / Mirror `[SyncVar]` | **154** | ⏸ Correctly skipped |
| DTO fields in nested/secondary classes | **11** | ↩ Converted then reverted (see below) |

Current tree state: **198** `[SerializeField] private` fields (153 converted + those authored in the
new Managers), **438** remaining `public` members matching a broad field-shaped grep (this figure
includes `public static`, `public const` and auto-properties, so it is a ceiling, not the true
remaining work — the actionable number is the **161** above).

#### Two traps hit, both fixed

1. **Expression-bodied members look like initialized fields.** A regex whose tail is `(?:=[^;]*)?;`
   matches `public Vector2 MoveInput => _moveInput;` because `=>` starts with `=`, silently producing
   an invalid `[SerializeField] private ... =>`. 4 occurrences, all in the new Manager files.
2. **A cross-*file* reference check is not sufficient.** C# does not let an enclosing type read a
   *nested* type's private members. This produced **81 `CS0122` errors** from same-file access. The
   11 affected members were all DTO/message fields and were reverted to public:
   `ShopManager.{CosmeticPreviewRule.CosmeticName, HatIconOverride.HatNameSubstring}`,
   `FishermanAnimationManager.{BodyPartAnimator.partName, AnimationInfo.rowLeft, AnimationInfo.totalFrames}`,
   `CustomNetworkManager.{GameModeMessage.gameMode, PlayerListMessage.allPlayerNames, SaltShopStateMessage.stateJson}`,
   `SaltShopService.{SaltShopState.windowStartUtcTicks, SaltShopState.ShopItem.displayName}`,
   `RoomRowPrefab.LANRoomInfo.fadText`.

   **Standing rule adopted:** leave fields of plain `[Serializable]` data/message classes public —
   they are DTOs. Only encapsulate MonoBehaviour fields.

Every failure in this phase was a **compile** error — loud, never silent.

## 3. Bugs found and fixed while testing

Both were **pre-existing**, confirmed by byte-comparison against the pre-restructure backup.

### 3.1 `BackManager` null on every scene after the first

- **Symptom:** clicking **Play** as the first action on Dash threw `NullReferenceException`.
- **Cause:** `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` fires *once per play session*. It
  created the BackManager inside the Splash scene; it is not `DontDestroyOnLoad`, so it died when
  Splash unloaded, leaving the static `instance` a dead reference for all of Dash.
- **Why it looked intermittent:** 15 files dereference `BackManager.instance` directly; only 5 use
  the self-healing `EnsureInstance()`. Opening Settings/Hints/Credits first repaired it by accident.
- **Fix:** also subscribe to `SceneManager.sceneLoaded` and re-run `EnsureInstance()` per scene.
  Deliberately **not** `DontDestroyOnLoad`, which would carry a stale stack of destroyed Buttons
  across scenes and break ESC.
- **Verified:** instance null `true → false`; objects in scene `0 → 1`; Play-first `NRE → OK`.

### 3.2 Blank white shop screen

- **Symptom:** the shop button opened an almost entirely white screen with one small parchment icon.
  No console errors.
- **Cause:** `ShopManager.ResizeToSpriteAspect` divided `canvasRect.rect.width` (**canvas units**,
  1920) by `rect.lossyScale.x` (**absolute world scale**). On a `ScreenSpaceOverlay` canvas
  `lossyScale ≈ 1` so it works by luck; this project's canvas is **`ScreenSpaceCamera`**, scaled to
  ~0.01. The Sal-T sign inflated to **22809 × 8236** and its opaque sprite covered everything.
- **Fix:** normalise the divisor by `canvasRect.lossyScale.x` — correct in both render modes.
- **Verified:** sign `22809×8236 → 211×76`; full shop UI renders.

## S2.6 Audio routing (spec §6) — done, without changing what you hear

The previous report's "12 direct `.Play()` call sites" was inaccurate: `ShopManager.cs:1868` is an
**Animator**, and two are inside `AudioManager` itself. There are **9** real sites.

`AudioManager.PlaySfx` was the wrong tool for them: it hands out a pooled one-shot voice, but
`boatMoveSound` is a sustained source with an explicit `.Stop()` (`FishermanController.cs:459`), and
every site uses an Inspector-configured `AudioSource` (loop, spatial blend, pitch) that a one-shot
would discard. Added instead:

- `AudioManager.PlaySource(AudioSource)` / `StopSource(AudioSource)` — **static and null-safe**, so
  audio cannot go silent if the manager is absent from a scene.

All 9 sites now route through `AudioManager`, satisfying §6, with **byte-identical behaviour**.

> **Volume is deliberately not applied in `PlaySource`.** Every call site already calls
> `GS.Instance.SetSFXVolume(source)` immediately beforehand, which writes `source.volume` from the
> same `SFXVolume` PlayerPref. Scaling again in `PlaySource` applied the setting **twice** — this was
> caught and removed before it shipped. Consolidating `GS`'s volume handling into `AudioManager` is
> the follow-up; until then `GS` owns volume and `AudioManager` owns routing.

### 2.2 Namespaces — complete

All **101 files** carry `namespace PanicAtThePond.<Module>` matching their folder.

Because the codebase is heavily cross-coupled (`GameManager` alone reaches into `FishController`,
`FishermanController`, `WormSpawner`, `JunkSpawner`, `HungerSystem`, `MashPhaseManager`,
`ScoreManager`, `GS`), every runtime file also received blanket `using PanicAtThePond.*;` imports for
the seven runtime modules.

- `Events`, `Interfaces`, `Enums` excluded from the blanket imports while empty — importing an empty
  namespace is `CS0246`. (`Interfaces` now has `IPoolable`, so it can be added when needed.)
- `Editor` excluded from runtime files — separate assembly.
- Encoding preserved byte-for-byte per file (BOM presence + line endings). These sources contain
  emoji and Hindi text inside `Debug.Log` strings that a naive rewrite would corrupt.

**Safety basis (verified, not assumed):** the codebase contains no `AddComponent("string")`,
`GetComponent("string")`, `Type.GetType()`, or `[SerializeReference]`. `CosmeticRuntimeApplier`'s
`script.GetType().Name` checks return the *short* name, which namespaces do not affect.

### 2.3 Infrastructure Managers — written, not wired

Five new files, authored to the ruleset's style rules (singleton `Instance` with duplicate-destroy in
`Awake`, `[SerializeField] private` + `_camelCase`, `UPPER_SNAKE_CASE` constants, XML `<summary>` on
public members, prescribed member order, cleanup method). **Purely additive — no existing script
references them, so runtime behaviour is unchanged.**

| File | Purpose |
|---|---|
| `Scripts/Interfaces/IPoolable.cs` | `OnSpawn()` / `OnDespawn()` hooks |
| `Scripts/Managers/PoolManager.cs` | Prefab-keyed pool: `Get` / `Release` / `Prewarm` / `Cleanup` |
| `Scripts/Managers/AudioManager.cs` | `PlaySfx` / `PlayMusic` / `StopMusic` over a fixed voice pool |
| `Scripts/Managers/UIManager.cs` | uGUI panel registry: `RegisterPanel` / `ShowPanel` / `HidePanel` |
| `Scripts/Managers/InputManager.cs` | Sole raw-input reader; exposes typed C# events |

Two deliberate design decisions:

- **`PoolManager` is for local objects only.** All 33 `Instantiate` sites are
  `PhotonNetwork.Instantiate` / `NetworkServer.Spawn`, which own their own net IDs and lifecycle.
  Pooling those is a networking redesign, not a refactor.
- **`AudioManager` reuses the existing PlayerPrefs keys** (`MasterVolume`, `MusicVolume`,
  `SFXVolume`) so it stays consistent with `GS` / `SettingsMenu` while call sites migrate.

### 2.4 Field encapsulation — partial by design

The rule is "No `public` fields". Converting `public X foo` → `[SerializeField] private X foo` is
**serialization-safe** because the field *name* is unchanged — every Inspector wiring survives.

| Category | Count | Action |
|---|---|---|
| Referenced only within their own type | **153** | ✅ Converted |
| Read cross-script (`GameManager.Instance.myFish`, …) | **161** | ⏸ Left public — needs a property + call-site updates |
| `static` / `const` / `readonly` / already-attributed / Mirror `[SyncVar]` | **154** | ⏸ Correctly skipped |
| DTO fields in nested/secondary classes | **11** | ↩ Converted then reverted (see below) |

Current tree state: **198** `[SerializeField] private` fields (153 converted + those authored in the
new Managers), **438** remaining `public` members matching a broad field-shaped grep (this figure
includes `public static`, `public const` and auto-properties, so it is a ceiling, not the true
remaining work — the actionable number is the **161** above).

#### Two traps hit, both fixed

1. **Expression-bodied members look like initialized fields.** A regex whose tail is `(?:=[^;]*)?;`
   matches `public Vector2 MoveInput => _moveInput;` because `=>` starts with `=`, silently producing
   an invalid `[SerializeField] private ... =>`. 4 occurrences, all in the new Manager files.
2. **A cross-*file* reference check is not sufficient.** C# does not let an enclosing type read a
   *nested* type's private members. This produced **81 `CS0122` errors** from same-file access. The
   11 affected members were all DTO/message fields and were reverted to public:
   `ShopManager.{CosmeticPreviewRule.CosmeticName, HatIconOverride.HatNameSubstring}`,
   `FishermanAnimationManager.{BodyPartAnimator.partName, AnimationInfo.rowLeft, AnimationInfo.totalFrames}`,
   `CustomNetworkManager.{GameModeMessage.gameMode, PlayerListMessage.allPlayerNames, SaltShopStateMessage.stateJson}`,
   `SaltShopService.{SaltShopState.windowStartUtcTicks, SaltShopState.ShopItem.displayName}`,
   `RoomRowPrefab.LANRoomInfo.fadText`.

   **Standing rule adopted:** leave fields of plain `[Serializable]` data/message classes public —
   they are DTOs. Only encapsulate MonoBehaviour fields.

Every failure in this phase was a **compile** error — loud, never silent.

## 3. Bugs found and fixed while testing

Both were **pre-existing**, confirmed by byte-comparison against the pre-restructure backup.

### 3.1 `BackManager` null on every scene after the first

- **Symptom:** clicking **Play** as the first action on Dash threw `NullReferenceException`.
- **Cause:** `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` fires *once per play session*. It
  created the BackManager inside the Splash scene; it is not `DontDestroyOnLoad`, so it died when
  Splash unloaded, leaving the static `instance` a dead reference for all of Dash.
- **Why it looked intermittent:** 15 files dereference `BackManager.instance` directly; only 5 use
  the self-healing `EnsureInstance()`. Opening Settings/Hints/Credits first repaired it by accident.
- **Fix:** also subscribe to `SceneManager.sceneLoaded` and re-run `EnsureInstance()` per scene.
  Deliberately **not** `DontDestroyOnLoad`, which would carry a stale stack of destroyed Buttons
  across scenes and break ESC.
- **Verified:** instance null `true → false`; objects in scene `0 → 1`; Play-first `NRE → OK`.

### 3.2 Blank white shop screen

- **Symptom:** the shop button opened an almost entirely white screen with one small parchment icon.
  No console errors.
- **Cause:** `ShopManager.ResizeToSpriteAspect` divided `canvasRect.rect.width` (**canvas units**,
  1920) by `rect.lossyScale.x` (**absolute world scale**). On a `ScreenSpaceOverlay` canvas
  `lossyScale ≈ 1` so it works by luck; this project's canvas is **`ScreenSpaceCamera`**, scaled to
  ~0.01. The Sal-T sign inflated to **22809 × 8236** and its opaque sprite covered everything.
- **Fix:** normalise the divisor by `canvasRect.lossyScale.x` — correct in both render modes.
- **Verified:** sign `22809×8236 → 211×76`; full shop UI renders.

## 5. What still needs to be done

Ordered by risk. Everything below **can break the game silently**, except where noted.

### Tier A — low risk, compile-checkable
1. **Wire `AudioManager`** — 12 direct `.Play()` / `PlayOneShot` call sites.
2. **Wire `UIManager`** — replace ad-hoc `SetActive` panel toggling.
3. **Reduce `FindObjectOfType`** — 22 call sites; several are legitimate one-time `Awake` lookups.
4. **Reduce `GameObject.Find`** — only 2 call sites left.
5. **Fill `Events/`, `Enums/`** — currently empty; add ScriptableObject event channels as features need them.
6. **Encapsulate the remaining 161 cross-script fields** — mechanical: add a public property per
   field, update call sites. Large but every error is a compile error.

### Tier B — medium risk, needs playtesting
7. **Input System migration** — 15 legacy `Input.GetAxis` / `GetKey` / `GetMouseButton` sites onto
   `InputManager` events. Blocked on a prerequisite: `PlayerControls.inputactions` currently holds
   only Unity's default template actions (`Move` / `Look` / `Fire`) with `generateWrapperCode: 0`,
   which do **not** describe this game. The asset must be authored to the real control scheme
   (Horizontal/Vertical, `W`/`S` rod select, hold `X`+`V` to cast, right-click reel, `Space` mash,
   `Q` drop junk, `Esc` back) before the ruleset's "generate C# class" step is meaningful.
8. **Scene root hierarchy** — `Managers / Systems / UI / Environment / Gameplay / Debug` across
   3 scenes and 1,431 components. Must be done in the Editor and diffed, not by text edit.
9. **Move `Photon/` and `TextMesh Pro/`** — feasible but requires patching 7 vendor files (Photon) and
   re-verifying TMP settings resolution.

### Tier C — high risk, fails *silently at runtime*
10. **`_camelCase` field renaming** — 563 fields. Unity serializes by field *name*, so every rename
    needs `[FormerlySerializedAs("old")]` **and** a re-serialization pass over all scenes and prefabs.
    Without both, 1,431 Inspector wirings across Dash (1089), Play (299) and Splash (43) silently null out.
11. **Asset naming conventions** (`SP_` / `M_` / `ANIM_` / `SFX_`) — breaks 104
    `Resources.Load("literal")` calls, the `iconResource` paths in `shop_config.json`, and
    `CosmeticRuntimeApplier`'s `name.Contains("blue_cap")`-style matching.
12. **Addressables** — package not installed; converts the entire cosmetics pipeline sync → async.
13. **Object pooling for spawns** — all 33 `Instantiate` sites are networked spawns; pooling them is a
    networking redesign.

**Recommendation:** do Tier A freely, Tier B with playtesting after each step, and treat Tier C as a
separate project with an explicit decision — the failure mode there is a silently broken build, which
directly contradicts the "no problems, runs smoothly" goal.

## 6. How to verify future changes

```bash
# health probe
npx unity-mcp-cli run-system-tool ping --input-file ping.json --url http://localhost:29620

# open a scene / read console / run tests
npx unity-mcp-cli run-tool scene-open        --input-file args.json --url http://localhost:29620
npx unity-mcp-cli run-tool console-get-logs  --input-file args.json --url http://localhost:29620
npx unity-mcp-cli run-tool tests-run         --input-file args.json --url http://localhost:29620
```

Gotchas: the plugin window's **Server URL** is authoritative for the port (29620), *not*
`UserSettings/AI-Game-Developer-Config.json` (which still says 21198). Use `--input-file`, never
inline `--input` (PowerShell mangles the JSON). Asset refs need
`{"instanceID":"0","assetPath":"Assets/..."}` — the key is `assetPath`, not `path`.

**Regression baseline:** with a scene open and not in playmode, the only console errors should be
`SteamAPI_Init() failed` / `Steam is not initialized!` (Steam client not running; `steam_appid.txt`
holds `480`) and the MCP plugin's cloud-auth retries. Anything else is new. Zero
missing-script-reference errors is the signal to watch after any file move.
